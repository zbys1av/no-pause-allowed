# Smart Video Cutter

Локальний настільний редактор пауз у записах малювання. Windows 10/11 x64 —
цільова платформа; ядро та Qt-інтерфейс також запускаються на Linux.
Відео не надсилаються в мережу, облікові записи й API не потрібні.

## Готова portable-версія для Windows

**[Завантажити Windows portable ZIP](https://github.com/zbys1av/no-pause-allowed/archive/refs/heads/portable-windows.zip)**

1. Завантажте архів за посиланням вище.
2. Розпакуйте **всю** папку з архіву.
3. Запустіть **SmartVideoCutter.exe**.

Встановлювати Python, FFmpeg, кодеки чи Qt не потрібно: усе є всередині.
Програма працює без адміністратора та без Інтернету. Папки `_internal` і
`tools` мають залишатися поряд із EXE. Для видалення достатньо видалити
розпаковану папку після закриття програми.

Це окрема готова збірка у гілці `portable-windows`. ZIP вихідного коду з
гілки `main` призначений для розробки. Інструкції нижче потрібні лише
розробникам, а не користувачам portable-версії.

## Стек і структура

Використано **Python 3.12–3.13 + PySide6/Qt 6.8 LTS + NumPy + FFmpeg**, замість
рекомендованого Tauri. Для цього застосунку Qt дає нативний відеоплеєр,
файлові діалоги й виділення області без вебсервера; NumPy виконує порівняння
кадрів у нативному коді. Це спрощує спільне використання й тестування локального
алгоритму та Windows-пакування. Компроміс — більший дистрибутив Qt/Python.

```
smartcut/
  video.py       FFprobe, метадані й орієнтація
  motion.py      потокові кадри, PTS, оцінка руху
  model.py       сегменти, padding, межі, статистика
  export.py      експорт і справжній preview за одним планом
  process.py     процеси, прогрес, скасування
  app.py         Qt UI, плеєр, область і таймлайн
tests/           контрольні відео й автоматизовані перевірки
scripts/         Windows portable/installer
uv.lock          зафіксовані залежності для платформ
```

## Запуск із вихідного коду на Windows (для розробки)

Потрібні Python 3.12 x64 та FFmpeg **6 або новіший** з `libx264`, AAC,
`showinfo`, `atempo`. Встановіть FFmpeg із перевіреного джерела,
наприклад через Windows Package Manager:

```powershell
winget install --id Python.Python.3.12 --exact
winget install --id Gyan.FFmpeg --exact
# Відкрийте новий PowerShell у корені цього репозиторію.
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install uv==0.12.23
.venv\Scripts\uv.exe sync --locked --extra dev
.venv\Scripts\python.exe -m smartcut
```

Перевірка доступності: `ffmpeg -version`, `ffprobe -version`.
Альтернатива PATH: покладіть `ffmpeg.exe` і `ffprobe.exe` у `tools/` поряд
із проєктом. Або задайте `SMARTCUT_FFMPEG` та `SMARTCUT_FFPROBE` повними
шляхами до виконуваних файлів. Значення не повинні містити аргументів команди.
Жодного автоматичного завантаження виконуваних файлів програма не робить.

## Linux / cloud development

Системні передумови: Python 3.12+, FFmpeg/FFprobe, EGL та PulseAudio libraries.
У Debian/Ubuntu: `sudo apt-get install ffmpeg libegl1 libpulse0`.

```bash
uv sync --locked --extra dev
uv run --locked --extra dev python -m smartcut
QT_QPA_PLATFORM=offscreen QT_AUDIO_BACKEND=pulseaudio uv run --locked --extra dev pytest -q
```

Для GUI потрібна графічна сесія. Offscreen придатний для автоматизації
інтерфейсу, але не замінює перевірку відтворення і звуку на Windows.
У cloud-середовищі Qt потребує дозволу на локальну ініціалізацію аудіо.

## Робочий процес

1. **Open Video** або перетягування одного MP4/MOV/MKV/WebM/AVI.
   З'являться назва, тривалість, орієнтовані розміри, середній FPS, розмір,
   формат і наявність аудіо. Підтримка декодування залежить від FFmpeg.
2. Перегляньте оригінал. Якщо Qt не відтворює кодек, натисніть
   **Compatible preview**: буде створено тимчасовий H.264/AAC proxy до 1280 px.
3. Налаштуйте sensitivity (80%), minimum idle (1.5 s), padding (0.4 s),
   частоту аналізу (6/s). **Custom Area**: призупиніть оригінал і протягніть
   прямокутник по полотну. Враховуються масштабування, letterbox і орієнтація.
4. **Analyze Video**. Декодування працює у фоновому потоці; Cancel зупиняє
   FFmpeg. Аналіз не запускається автоматично при русі повзунків.
5. Зелений — Keep, червоний — Remove, бурштиновий — Speed Up. Натисніть
   сегмент на таймлайні або в таблиці, щоб перейти до його початку.
   Відредагуйте дію та межі в секундах і натисніть Apply. Зміна межі також
   змінює суміжний сегмент: прогалин і перекриттів не виникає.
   Перший початок та останній кінець фіксовані. **Reset automatic** скидає ручні зміни.
6. **Remove Idle Sections** або **Speed Up Idle Sections** (2/5/10/20×).
   Зміна mode/minimum/padding перебудовує план із кешованих результатів і
   скидає ручні зміни; зміна sensitivity/frequency/area потребує повторного
   Analyze і позначає попередній план застарілим. Зміна швидкості оновлює
   наявні speed-сегменти, зберігаючи їхні межі та ручні рішення.
7. **Edited** створює реальний тимчасовий MP4 із поточного плану, а не
   приблизну імітацію переходів. Прогрес і статус видимі; після редагування
   старий preview більше не використовується. Original повертає джерело/proxy.
8. **Export Video**: MP4 H.264, CRF 18/23/28, Preserve Audio або Mute Video,
   шлях збереження. Прискорене аудіо обробляється ланцюжком `atempo` зі
   збереженням висоти тону. CPU — типовий варіант; NVENC/QSV/AMF доступні
   за наявності відповідного обладнання, драйвера і збірки FFmpeg.
   Помилка апаратного енкодера не приховується; виберіть CPU для повторної спроби.

Існуючі вихідні файли та оригінал **ніколи не перезаписуються**. Оберіть нову
назву. Файл публікується лише після успішного завершення. Усі тимчасові
фрагменти експорту прибираються при помилці/скасуванні; preview — при закритті.
Закриття під час обробки спочатку скасовує роботу й чекає завершення процесу.

## Алгоритм і обмеження

FFmpeg декодує послідовно; `select` пропускає зайві кадри перед масштабуванням.
Залежні кодеки все одно потребують декодування проміжних кадрів. Аналізується
grayscale-копія завширшки 320 px (максимальна висота ROI 360), зберігаються
лише два кадри та компактні timestamp/score/active записи. Оригінал не
перекодовується під час аналізу. `showinfo` дає PTS обраних кадрів після
нормалізації початку: немає припущення про сталий FPS.

Порівняння компенсує глобальну зміну яскравості медіаною різниць, відкидає
низькоамплітудний шум і поодинокі змінені пікселі. Sensitivity змінює як
поріг різниці, так і мінімальну частку змінених пікселів. Це евристика:
мерехтіння, рухоме зерно й дуже дрібні штрихи можуть вимагати налаштування
ROI/чутливості. Точність меж обмежена інтервалом вибірки та кадрами джерела.
Дуже короткі статичні відео (<minimum idle) зберігаються цілком.
Повністю статичний довгий запис не експортується порожнім: залиште сегмент вручну.

Експорт послідовно перекодовує збережені сегменти з оригіналу, потім об'єднує
їх; це обмежує RAM і розмір одночасного filter graph. Проміжне аудіо — PCM,
AAC кодується один раз після склеювання, щоб не накопичувати encoder priming.
Потрібне вільне місце поряд із призначенням (усі проміжні відео й PCM плюс MP4).
Помилки диска/прав доступу показуються, частковий кінцевий файл не залишається.
Файлова система призначення має підтримувати hard links (NTFS, ext4 тощо).

VFR приймається й експортується з `-fps_mode vfr`; можливе округлення меж
до кадру та AAC-пакета. Не обіцяється бітова тотожність таймінгу.
Роздільна здатність оригінальна; для непарних розмірів додається максимум
один піксель краю для H.264/yuv420p. HDR/10-bit перетворюється в 8-bit SDR
без спеціального tone mapping: для HDR цей випуск не призначений.
Береться перша відеодоріжка і перша аудіодоріжка; субтитри й інші доріжки
не копіюються. Сесії монтажу поки зберігаються тільки в пам'яті.

## Перевірки

```powershell
.venv\Scripts\python.exe -m pytest -q
```

Тести генерують відео FFmpeg: 10 s статичного кадру, 5 s руху / 5 s паузи /
5 s руху, дрібні зміни, шум, ROI, VFR, пошкоджений файл, відсутність відео.
Перевіряються padding, ручні межі, статистика, mute, proxy, скасування,
тривалість експорту, порядок кольорових кадрів, відсутність чорних кадрів,
частоти аудіомаркерів до/після монтажу, усі швидкості та незмінність оригіналу.
Qt-тест перевіряє ручне редагування, reset та блокування застарілого плану.

Поточний Linux запуск не доводить готовність Windows-дистрибутива.
Перед випуском перевірте на реальних Windows 10/11: drag/drop, відео/звук,
поворот/ROI, нетипові кодеки/proxy, експорт довгого VFR, Unicode-шляхи,
місце на диску, cancel/close і доступні апаратні енкодери.

## Відтворення portable-збірки (для розробників)

На Windows x64 потрібні Python 3.12 та uv. Один сценарій завантажує
залежності, перевіряє SHA-256 FFmpeg за зафіксованим маніфестом Microsoft
WinGet, запускає тести, збирає EXE, додає Python/Qt/FFmpeg і ліцензії,
створює ZIP, розпаковує його в іншу папку та перевіряє готовий EXE.
Користувач portable-версії нічого з цього не виконує.

```powershell
python -m pip install uv==0.12.23
powershell -ExecutionPolicy Bypass -File scripts\build_windows.ps1
# Необов'язковий інсталятор, якщо встановлено Inno Setup 6:
powershell -ExecutionPolicy Bypass -File scripts\build_windows.ps1 -Installer
```

Результати в `dist/`:

- `SmartVideoCutter-Windows-x64-portable.zip` — готовий архів;
- `SmartVideoCutter-Windows-x64-portable.zip.sha256` — контрольна сума;
- `portable-check.json` — результат перевірки готового EXE.

Self-test запускається всередині зібраного EXE з PATH, що не містить
системного Python чи FFmpeg: генерує відео, аналізує рух, експортує зі
звуком і декодує кадр у Qt. Ліцензії та інформація про походження FFmpeg
копіюються автоматично; вручну підкладати виконувані файли не потрібно.
Завантаження залежностей відбувається тільки при збірці, не в portable-додатку.

Workflow `.github/workflows/portable.yml` повторює це на Windows і публікує
ZIP у GitHub Releases після успішних тестів. Для його запуску GitHub Actions
має бути доступним для акаунта. Наявна portable-гілка завантажується без Actions.

Підписання коду сертифікатом Windows не налаштовано; пакет не є підписаним.
